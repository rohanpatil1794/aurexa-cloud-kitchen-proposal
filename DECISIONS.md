## Rendering and performance

### Look and lighting

- Environment cube: a gradient dome (warm floor bounce below, cream at the horizon, a darker cool sky above) plus four panels, with key / hemisphere / env levels balanced around it. The old cube was black except for its panels, so every steel face seen at eye level mirrored black. The panels are plain meshes with Lightformer's material so their colours can be damped between Day and Evening; the cube re-renders only while the toggle eases. drei's `<Environment>` resets scene.environmentIntensity to 1 each time it re-renders: Lighting re-applies its eased value in a layout effect after it.
- Key light: a south-west DirectionalLight whose shadow camera is re-fitted to the model whenever the light moves. A camera-attached fill (directional, no shadow, 0.8 day) fades in below 16 ft camera height and is off above 42 ft, so eye-level and room-overview views show faces turned away from the key while the aerial keeps its modelling. The fill is always present (intensity 0 when off) so the program key never changes.
- Evening is a cool dusk, not a brown filter: key lower and mildly warm (#ffd6b0, 1.3), blue hemisphere and dome, backdrop easing to deep blue, zone tints 30% further and 35% more saturated so the five zones stay distinct. Practicals (EveningGlow.tsx): warm additive light pools under every ceiling light (the Ceiling's panel grid) plus two in the garden, and halos round lamp-like emissive parts (hood lights, heat lamps, lanterns, festoon, ring light) found by reading the equipment batches once. Both are hidden in Day; the pools keep renderOrder 3.
- Flipping a material between opaque and transparent sets needsUpdate (three bakes `transparent` into the program as the OPAQUE define, so a program first compiled opaque ignored opacity afterwards).

### Render loop and quality

- The canvas runs `frameloop='demand'`. RenderGovernor draws while something changes (any store change or the camera moving, each for a settle window of 3 s / 3.6 s; flow ribbons, safety pulses and the hero turntable continuously; a selected room's outline pulse at ~30 fps) and otherwise draws nothing, so a static explorer costs no CPU or GPU. Camera components within 5e-4 count as not moving (camera-controls jitters by an ulp every frame). The loop is 'never' while the stage is off screen (IntersectionObserver, 80 px margin), the tab is hidden, or the shaders are still compiling. drei's PerformanceMonitor is gone: under 'demand' it reads every idle gap as a slow frame.
- Quality is a pixel-ratio ladder: tier 0 = the device ratio clamped to 1.5-2 on desktop (1-1.5 on touch or narrow screens, so 1.5 supersamples a 1x desktop screen: thin rails and pipes alias at 1), tier 1 = at most 1.25, tier 2 = 1, all capped at 8.5 M pixels (a 1.5x supersampled 4K window would need ~300 MB of MSAA buffers). It steps down after two slow ~0.8 s windows (mean over 27 ms) of a continuous run, probes back up after 25 s (at most 2 failed probes). `store.quality` is 'high' at tier 0 and 'low' below. `?quality=low` pins tier 2 and `?quality=high` tier 0 (diagnostics; also disables stepping).
- Shadows: the key light's map is cached (autoUpdate off) and re-rendered only when a caster can have changed: wall height moving, the Equipment layer toggling (plus a 0.6 s settle for React's commit), the key easing (Day / Evening), map re-creation, a context restore. The map size does not depend on quality (2048 desktop, 1024 touch), so a quality flip never rebuilds the render target. Parts smaller than 0.3 ft default to shadow:false; round parts with radius < 0.25 ft use 10-segment cylinders / 10 x 7 spheres (about 40% fewer triangles overall; a few more draw calls for the extra buckets).
- WebGL context loss: `preventDefault` so the browser can restore it; on restore the environment cube is redrawn (Lighting re-dirties itself) and the shadow map refreshed; if the context never returns within 4 s the renderer is unmounted without forcing a second loss (three warned about WEBGL_lose_context) and the floor-plan fallback shows.

### Boot

- The WebGL probe is out of the render path: one throwaway context after first paint, released at once (no probe at all would let three log console errors on a machine without WebGL). The Stage chunk starts the sign / label font downloads and the floor-texture worker as soon as it runs.
- Scene mounts four boot groups (light + camera, plinth + floors + walls, equipment, entrance + pickup + north arrow), each as a React transition, so one task per group and the render is also sliced at component boundaries (the equipment builder and its PrimBatch are two tasks). The creation order is the old one on purpose: three draws opaque objects in material-id order and changing it moved a few coplanar pixels. Each group starts its shader programs linking while the next is built; BootGate then uploads the textures (the 9 MB sign atlas, floors, flows) with gl.initTexture and reads each program's uniform table as it reports ready (KHR_parallel_shader_compile), all in 10 ms slices, and only then lets the loop run, so the splash never freezes on one multi-second task. checkShaderErrors is off in production.
- What the hero cannot show mounts after it (the LATE groups in Scene.tsx, one task each from 400 ms after the hero, 60 ms apart): picking + labels, the ceiling, flow ribbons, safety, dimensions, the evening lamps. A switch the visitor reaches first (entering the explorer, a layer, full height / eye level, Evening) mounts its group on the spot (lateNeeds), so nothing is ever missing, only built later; a mounted group stays mounted. The first toggle of a not-yet-built layer takes the build once (flows ~0.15 s at 1x, ~0.6 s at 4x). Late groups get the same compile + warm-up behind the running frames. EveningGlow's pools keep renderOrder 3 (3.5 changed ~0.1% of the Evening frame).
- LoadingSplash watches #stage with an IntersectionObserver and releases the splash (store.setSceneReady) as soon as the stage is off screen, because the canvas draws no frames there: it covers reloads with a restored scroll position, links and scripts that scroll during the boot. The scene keeps building behind the page and draws when the stage scrolls into view. stageLayout.topBarHeight treats a canvas that is completely off screen as resting at the top of the viewport, so a scene built while scrolled away still frames the model in sight.
- Sign fonts: the three weights are requested when the Stage chunk loads (Stage.tsx), long before the first sign is drawn, and a draw that did find a weight missing is repainted once when all three are in (it used to repaint every atlas and text texture five times, ~0.7 s of the boot under 4x). The glyph loop measures each character once per size.
- Floor textures: the six detail maps are painted in a module worker (floorWorker.ts; painters shared in floorPainters.ts) and handed over as bottom-up RGBA buffers for a DataTexture. Output is byte-identical to the canvas path, which stays as the fallback and paints whatever the worker has not delivered, so a missing worker / OffscreenCanvas only costs ~0.1 s (0.4 s throttled). Floor textures share one noise table and circulation reuses the cream texture.
- Measured (production build, 4x CPU throttle, 1440 x 900, median of 7 interleaved runs against the same build without the boot changes): hero up at 6.2 s instead of 8.2 s, main-thread CPU to the hero -23%, longest pre-hero task 1.19 s -> 0.72 s; 390 x 844 at 4x 9.0 -> 6.7 s; 6x 15.7 -> 11.8 s; 1x 2.8 -> 2.4 s. Screenshots (hero, explorer, layers, full height, evening, phone) match the old build to the pixel noise floor (at most 0.003% of pixels differ by more than 8/255). Still over 700 ms at 4x: the first script evaluation (index / vendor, then the Stage chunk) and the equipment's PrimBatch task (sign atlas: ~360 ms cold canvas-font setup, ~320 ms whole-atlas pixel passes).
- Tried, no gain over run-to-run noise, not landed: skipping the environment re-render on Lighting's first run (under 1%), starting the Stage chunk import from main.tsx (-75 ms), quantising sign font sizes (different glyph pixels), a 2-frame ReadyGate (frames 2 and 3 cost ~65 ms together).

## Camera and UI

### Framing and the layout rule

- Poses are framed, not scaled. Every orbit pose (hero, presets, room overviews) carries a `frame` (world points to keep on screen, data/cameras.ts) and CameraRig's fitFrame dollies the camera until those points fit the part of the screen the UI leaves free (stageLayout.ts: below the top bar, left of the 360 px panel, above the phone sheet), then camera.setViewOffset centres them there (not a camera move, so perspective and picking stay exact; dollyToCursor is off because a view offset would skew cursor-anchored zoom). Dolly is capped at 3.4x the authored distance. Portrait screens also swing the aerial / hero view towards frontal and higher, and eye level widens its lens (lookFov). Window resizes refit (150 ms debounce, only while the visitor has not orbited or zoomed since the camera last went somewhere), and a resize round trip lands on the same distance as a fresh load. The 10 ft goods-lift shaft, the north arrow and (in plan) the 60 ft dimension line clear the bar at 1280 x 720 to 1920 x 1080. This replaced the earlier fixed panel shift, FRAME_LIFT / FIT_ASPECT and fitOrbitPose.
- Hero: the camera measures the headline (text lines, not the box) and puts the model in the larger free area (stageLayout.heroFree), beside the text on landscape screens and above it on portrait ones, fitted at every turntable heading; the scrim is only a feathered left gradient. The turntable stops only when the visitor drags the model (not on a wheel tick or a page-scroll swipe) and starts again 3 s after they let go. Targets sit on the plinth's centre column so the turntable never swings the model.
- One layout rule, data/cameras.ts `isSheetLayout(w, h)`: bottom sheet for width < 768, or portrait (height >= width) up to 1100 px wide; side panel for everything else (landscape tablets from 1024 x 768 keep it; landscape phones 768 px or wider and at most 500 px tall, e.g. 844 x 390, fold the panel into an Explore drawer via isShortScreen; narrower ones get the sheet). stageLayout.explorerFree / hasRoomCard, CameraRig's layout key and the explorer UI (lib/hooks useSheetLayout, which measures the #stage box the canvas fills) all call it, so framing, labels and UI cannot disagree. `useIsMobile` stays width < 768: it only drives the top bar's burger menu (Tailwind md) and, with isMobileNow (also touch screens), the pixel-ratio and shadow-map choices.
- Open: layers/Dimensions.tsx still tests the width alone (size.width >= DESKTOP_MIN_WIDTH, and SHEET_LIFT for the sheet clamp) and NorthArrow's compact resting spot still uses a width-only 720 px test: both should move to !isSheetLayout(w, h) / isCompactStage. SHEET_LIFT (data/cameras.ts) survives only for that Dimensions clamp.

### Camera behaviour

- Touch orbit turns at half the mouse speed and stops 28 degrees above the horizon (mouse 10); the pose's own angle is always reachable, so Entrance and room views still work. Room overviews on desktop fit the room into the area right of the room card when that costs at most 1.3x the distance, otherwise shift it clear of the card.
- Eye level raises the walls to full height itself (store.wallModeBeforeEye remembers dollhouse and every other camera move puts it back; picking a wall mode by hand wins). Flights into, between and out of eye level are crane moves (up to 16 ft over the walls, straight down onto the spot, looking where the eye will look) so they never cut through geometry; the lens changes in the last 45% of the way in and the first half of the way out. The Hot Kitchen preset looks down at 66 degrees (1.15x further out) in full-height mode, which hides as little behind the 10 ft south wall as the authored 39 degrees does behind the 3.5 ft one; store.setWallMode re-poses it when it is the active preset.
- Eye views: rooms where the longest-door default pushed the lens against equipment or a blank wall have hand-picked vantage points (data/cameras.ts EYE_VIEWS: doorway, or just outside the door, looking in; at least 1 ft from every wall and floor-standing item, checked offline against the equipment data). The rest keep the longest-door rule (just inside the door with the longest sightline, 5.5 ft eye height).
- Zoom: camera-controls' own wheel action is off in every mode; the plain wheel always scrolls the page (the stage is a sticky section; it also stays the page's during the hero). CameraRig.zoomBy() does all zooming: Ctrl / Cmd + wheel over the model (preventDefault, so no browser page zoom; over the panel, sheet or other UI the browser zoom stays), trackpad pinch (Ctrl + wheel in Chrome / Firefox, gesture events in Safari on a Mac), touch pinch (camera-controls) and the on-screen + / - (store.stepZoom, ui/explorer/ZoomControls.tsx). A mouse notch is 1.2x, a button press 1.3x, a pinch zooms continuously (e^(0.01 x delta), delta clipped to 30); it eases with a 0.25 s glide (the 0.6 s resting glide is restored 0.7 s after the last zoom), steps accumulate from where the camera is heading, distance is clamped to 12 ft and 220 ft (or 1.25x the pose's distance if larger), a jump under prefers-reduced-motion; at eye level it changes the lens (0.75x to 2.2x). The + / - pill sits at the top-left under the Back chip on the panel layout, under the bar on the sheet layout (a row instead of a stack under 700 px tall, hidden while the sheet is full). The Views tab lists exactly what works.
- Store: prefers-reduced-motion is followed live (turntable stops, flights become jumps).

### Explorer UI

- Panel, room card and legends share one glass density (.explorer-card, rgba(8,22,23,.72)) rather than the .62 default: in close-up views the model fills the screen behind them and .62 let bright floors wash out the secondary text.
- Legends are one slim key card at the bottom-left (above the sheet on phones): swatch + name for each active workflow, icon + count for the safety layer; its 'i' button opens the full legends (route summaries, marker names) above it as part of the same flex stack, so the stack's height limit applies. While a room card is open (or under 760 px tall) the key stays one line; the safety legend on phones shows only while the sheet is peeking. Elements the labels must keep clear of carry `data-label-obstacle`.
- Picking a camera preset from Views also clears any selected room (clearSelection, then goPreset), so the room card never lingers over a camera that has left the room; a phone sheet then drops to peek, and picking a room from a full-height sheet drops it to half. On phones the room card puts Overview / Eye-level and Previous / Next above the purpose and notes, so the controls stay in reach at the 52% half height. Sheet constants (SHEET_PEEK_PX 76, SHEET_FRACTION half 0.52 / full 0.88) live in data/cameras.ts.
- The room card is split into head / notes / controls (InfoCard.tsx); on desktop the controls are pinned under the scrolling text, and only the texts are keyed by room, so Previous / Next keep keyboard focus. A keyboard pick (a click with detail 0) moves focus to the card's heading (ui/explorer/focus.ts); Esc, Back or the chip returns it to the room's row (or the active tab on phones); a polite status line announces picks made in 3D.
- Eye level swaps the card for RoomBar (name, size, Overview / Eye-level, Previous / Next, Notes, Back) so the walk-through keeps the lens; on phones it sits above the peeking sheet (eye level drops the sheet to peek, leaving it lifts it to half). Short screens always use the bar. The bar is a grid placed by a container query on its own width (>= 44 rem: one 62 px row; narrower: name + close on row 1, controls on row 2), never a wrapping flex row, so the close button cannot drop to a third line; the name wraps (line-clamp 2) before anything is cut off; a fixed 56 rem width (capped by its container) keeps Previous / Next still while stepping. Checked for all 23 rooms at 1920, 1280, 1024, 768, 844 x 390, 390 and 360 wide.
- The canvas owns every touch in the explorer, so the way on to the proposal is a "Continue to the proposal" row at the end of the desktop panel and a Proposal chip (ProposalChip.tsx) beside Back on phones.
- Touch screens of any width get 44 px targets in the explorer through one rule (`@media (pointer: coarse)` on [data-explorer] buttons and selects); the phone sheet's handle is the exception (32 px; the 76 px peek is fixed).
- The page's one h1 is screen-reader-only and always mounted (Hero.tsx); the visible hero title is a decorative paragraph. Panel group headings are h2 (h3 under a room name), and only the selected tab carries aria-controls.
- With no WebGL, `#stage:has(.webgl-fallback)` (index.css) hides the hero and the explorer: the fallback is the whole stage (studio line, headline, plan, "Continue to the proposal", floor-plan download). No store flag is needed.
- Colour and contrast: orange (#cb622a) never carries white or cream text (3.1 to 4:1): section buttons, the hero CTA label, the explorer's selected rows, active presets and segmented pill all use ink text on it (4.6:1). Teal on sand is 4.2:1, so small text on the sand Safety section is ink and only the large H2 stays teal; focus rings are teal (cream on the teal band).

### Top bar, hero and splash

- TopBar is fixed at z-50 with height var(--topbar-h) (56 px phones / 64 px desktop, plus the safe-area inset); the loading splash is portalled to body at z-100 so it also covers the bar. Explorer UI starts below var(--topbar-h). The bar spans the viewport like the explorer overlays (no max width).
- The bar is dark (white lockup) while the stage, or a linked section whose computed background is dark, sits under it, and cream-frosted otherwise; no per-section attribute needed. The stage counts as 'under the bar' while its bottom edge is below the bar's centre line, like every other section, so a nav jump that parks the next section flush under the bar keeps it dark. Its three backings crossfade by opacity and are visibility:hidden when inactive, so no blur runs over the live canvas needlessly. Nav jumps scroll the section flush under the bar (ui/nav.ts, own offset, not scroll-mt).
- While the hero is up the stage's canvas wrapper gets `touch-action: pan-y !important` (CSS :has(.hero-root)): camera-controls sets an inline `none` there, which beat the canvas's own value. Phones can still scroll the page by swiping; horizontal drags orbit.
- Hero layout: the text column is 30 rem with a smaller title; the side-by-side layout is the `wide:` variant (width >= 768 and landscape), so portrait tablets get the phone layout (model above, text below); screens under 560 px tall (landscape phones, 400% zoom) get a compact left-aligned stack with the subline dropped under 400 px. CubeMotif is redrawn from the logo geometry (isometric W 122 / H 70.5 / L 141; variant solid = logo tints, outline = visible edges only).
- index.html carries a static copy of the loading splash inside #root (same .splash classes) plus html { background: #070d0e }, so cold starts are dark from the first paint; React replaces it and mounts its own splash in the same commit. The splash plays no entry animation (it would restart at the hand-over); only the line sweep runs. The mark and wordmark are preloaded.

### Labels, picking and selection

- Labels: one DOM layer driven by a single useFrame (not one drei <Html> per room), appended beside R3F's event element (pill pointer events bubble into the scene's picking); one loop projects, fades, resolves overlaps and z-orders all 23 pills. `pillPointer.over` (labelsLayout.ts) stops R3F's late "pointer left the canvas" from clearing a hover a pill has just set. Enter / fade timers use performance.now(), not the R3F clock: setFrameloop restarts the clock from 0, which used to keep every pill at opacity 0 after the stage had been off screen. The top-bar reach is re-measured on resume and every 20 frames.
- Overlaps: pills that would overlap are stacked / shifted on screen (Declutter, smallest rooms keep their spot) and tied to their room's floor centre by a thin stem when moved more than 14 px. The settled layout is a pure function of camera + viewport + selection (+ hover): Declutter keeps no preference for its last candidate and the dot / pill choice has one threshold (MINI_AT, no hysteresis); only the eased glide towards the result has memory (candidates are a finer lattice, quarter widths, half rows). Every [data-label-obstacle] element (panel, sheet, room card, chips, legends) and the north compass (NORTH_ARROW_RECT) is a keep-out rectangle, and no pill covers ANOTHER room's floor-centre click target (a 6 px + gap keep-out; the room's own pill may). The clamp keeps pills inside stageLayout.explorerFree.
- Compact labels follow the model size a stage can show, min(free width, 1.3 x free height) < 720 px (isCompactStage in labelsLayout.ts), not the free width alone, so landscape phones get one-word pills (LABEL_SHORT, 9 px type) and dots too. A room much smaller on screen than its pill shows a 15 px zone-coloured dot (33 px hit area) instead; hover, tap or selection turns it back into the pill. At 390 px wide that keeps about seven pills on a phone aerial and the selected room clear.
- A drag that starts on a pill or dot orbits like a drag on the canvas: both faces are touch-action: none and display: block (touch-action does not apply to the inline box `all: unset` leaves on the dot), the press is re-sent to the canvas as a synthetic pointerdown (RoomPicking ignores untrusted ones), a tap (under 6 px mouse / 10 px finger) still selects. Verified with CDP touch events.
- Visibility: orbit views show every label and fade them only for near-horizontal views (camera below ~24 degrees above the label); eye level keeps labels within 12-32 ft; in full-height mode labels hide while the camera is under the ceiling. Other labels dim while a room is selected (less the further they are from it); the selected pill is orange, hovered pills reveal the area tag.
- Picking: the cursor is set inline on the canvas (the stage CSS gives the canvas its own `grab` cursor, which `document.body.style.cursor` would not override). Hover is ignored while a mouse button is down (orbiting); on touch the tint shows only while the finger is down. The selection loop is drawn on the floor (just inside the wall faces) and on the wall tops (above the ceiling slab in full height), with its on-screen width kept near 5.5 px whatever the camera distance.

## Equipment

Everything is built from primitives by kind builders (src/scene/equipment/kinds/*) into instanced batches.

- Materials: large stainless / sheet-metal faces (cabinet bodies, doors, hood back / apron / caps, ducts, cladding, bench tops, sinks, fridge cabinets, ovens, proofer, freezers, lift shaft) use the 'gloss' material with a light satin colour (prepKit SATIN_STEEL, productionParts PANEL, kitchen line colours) instead of 'steel': inside the closed building metalness mirrors only the dark environment floor and a big steel face reads black. Tops, knobs, rails, legs, shelves and handles stay 'steel' (metalness 0.78 / roughness 0.4, a little diffuse, never a pure mirror). Copper cookware uses gloss paint rather than brass metal (north-facing metal reads black at eye level).
- Near-black albedo sweep: dark painted colours cannot be relit, so UPS cabinets went from #2d363b to a mid slate #64717a with a light top cap and door frame; stair steel, goods-lift frame, plinths, wok housing, induction glass, cast-iron rings, mats and device bodies were lifted to mid slate (shared SLATE in kindKit, KL.dark in kitchenLineParts). Emissive LEDs, screens and the deliberately dark sign backs stay dark.

## Build and deploy

- Pinned to React 18.3 / @react-three/fiber 8 / drei 9 / three 0.170 (the stack the brief names) with Vite 7, TypeScript 5.9 and Tailwind CSS 4 (CSS-first config). camera-controls is a direct dependency (CameraRig imports it).
- Wall geometry module is src/scene/building/wallModel.ts (NOT walls.ts): on Windows / macOS walls.ts and Walls.tsx collide (extensionless './Walls' resolves to walls.ts first, and tsc raises TS1261 casing errors), so the pure model and helpers (wallBoxesIntersectSegment, wallCrossings, WALL_MODEL) live in wallModel.ts.
- index.html is a template. Its {{SITE_TITLE}} / {{SITE_DESCRIPTION}} / {{STUDIO_NAME}} / {{OG_DESCRIPTION}} / {{OG_IMAGE}} / {{OG_IMAGE_ALT}} tokens are filled from src/config.ts by the html-meta plugin in vite.config.ts (dev and build), so the tab title and link previews follow the config. og:image / twitter:image are made absolute (crawlers do not resolve a relative URL) from SITE_URL or Vercel's VERCEL_PROJECT_PRODUCTION_URL; when neither is set they stay /og.png and the build prints a warning.
- Fingerprinted JS / CSS / fonts are emitted to dist/static (build.assetsDir) instead of dist/assets, because public/assets/floorplan.png is not fingerprinted and lives in /assets; this lets vercel.json cache /static as immutable and keep /assets revalidated.
- The Stage is loaded with React.lazy (scene/LazyStage.tsx), so the first paint needs only the vendor (react) and index chunks (about 140 KB gzipped); three, r3f, drei, camera-controls and the scene (about 330 KB gzipped) load afterwards in parallel, plus a small module worker for the floor textures. A chunk that fails to load shows the WebGL fallback (floor plan) and releases the splash instead of blanking the page. manualChunks pins only react / react-dom / scheduler (vendor) and three; everything else follows its importers.
- Public Sans is declared with woff2-only @font-face rules in src/index.css (the six .woff duplicates that @fontsource/*.css adds are gone from dist); the 400 / 500 / 600 files the hero uses are preloaded by the preload-fonts plugin; textTexture.ts also waits for the 500 and 800 weights (small second lines, EXIT / GAS / name-plate signs).
- Shared links work (lib/deepLink.ts): /#vision, /#zones-flow, /#safety, /#design-language, /#contact (any element id) scroll to that section flush under the top bar and release the splash (the Canvas does not draw while the stage is off screen); /#stage opens the explorer once the scene is ready. The nav writes the hash on a click (history.replaceState), not while scrolling. ?quality=low|high is the only query parameter.
- vercel.json: framework vite, immutable caching for /static, revalidation for html and the un-hashed public files (an hour for /assets, /brand, favicons and og.png), X-Robots-Tag noindex plus a CSP (self only, inline styles allowed, blob / data images, worker-src self + blob), X-Frame-Options SAMEORIGIN, nosniff, a strict Referrer-Policy and a closed Permissions-Policy. No rewrites: the site is one page with hash links.
- Node: package.json `engines.node` is `^20.19.0 || ^22.12.0` (Vite 7's floor, capped below 23). Vercel lets `engines` override the Node version in the project settings, and takes the newest supported major that fits the range, so builds run on 22.x and never jump to a future major unannounced (the earlier open range `>=22.12.0` also matched 24+). To change the Node version, change `engines`, not the dashboard.
